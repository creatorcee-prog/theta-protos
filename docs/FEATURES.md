# Features (v0.3): how they plug in, and who builds what

Every feature is its own files. Nobody edits another feature's files.

## The hookup

### Server
`server/ext.py` loads each module named in `FEATURES` (`google gcal routines workflows subagents media browser calls`).
A module may define any of:
- `TOOLS`, `RELEVANT`
- `ROUTES` and `PUBLIC_ROUTES` (public routes must verify the caller themselves)
- `JOB_KINDS`
- `tick(now)`, `connections()`, `context(bot, now)`

The exact contract is in the docstring at the top of ext.py. A missing or broken module is skipped.

### Tools
Tools use the shape in `server/tools.py` (name, risk, description written like docs for a new hire, params, run,
preview). The risk levels:
- `"read"` runs freely.
- `"write"` runs freely but only changes the user's own things.
- `"send"` never runs inside the model loop. It becomes an Approve/Discard card, and `run_approved` executes the
  stored arguments exactly, only after the user taps Approve. Anything that reaches another person, spends money,
  submits a form or deletes something is "send".

Outputs that contain outside text (web pages, emails, files) set `untrusted: True`.

### Storage
`db.get_setting` / `db.set_setting` (JSON values) and `db.add_job(due_t, kind, payload)` with your own
`JOB_KINDS`. A feature needing a table creates it itself with `CREATE TABLE IF NOT EXISTS`, through
`db._conn()`. Files go under `os.path.join(db.data_dir(), "<feature>")`, or `$PROTOS_DATA`.

### Sending a text plus a push
```python
m = db.add_message("theta", "assistant", text, {"proactive": True, "source": "<feature>"})
push.notify("Theta", short, f"/?m={m['id']}")
```

### Running a turn from code (routines, sub-agents)
`from server import models, router, persona, agent, tools`. See `app._agent_turn` for how a turn is put together.

### Web
`web/features/<name>.js` is loaded after app.js and uses `window.Theta`:
- `Theta.api(path)` and `Theta.post(path, body)`
- `Theta.toast(text)`, `Theta.send(text)`
- `Theta.sheet(id, title, onOpen)`: returns `{root, body, foot, pill}`
- `Theta.open(id)` and `Theta.close()`
- `Theta.menu(label, icon, sheetIdOrFn)`
- `Theta.settings(title, tab)`: returns a `.group` to fill with `.row-set` rows, in the Settings tab `tab`
  ("general", "notifications", "connections" or "security"; known titles pick their own, else General)
- `Theta.open("settings", "connections")`: opens Settings on a tab. `Theta.logo(app)` makes an app tile with its brand logo
- Apps not built yet are listed in `server/catalog.py` and show as "Soon" under Connections; brand logos are
  `web/logos.js`, generated by `web/icons/make_logos.js` from Simple Icons (CC0)
- `Theta.decorate((msg, row, bubble) => ...)`
- `Theta.el(tag, cls, text)` and `Theta.svg(iconId)`
- `Theta.md(text)`: safe markdown to DOM

Build DOM nodes only, never `innerHTML` with server or model text. In demo mode (`Theta.state.demo`), show a
short note instead of calling the API. Styles go in a `<style>` element the script adds, prefixed with the
feature's id.

### Tests
Each feature gets `tests/test_<feature>.py`: stdlib only, no network (stub `urllib.request.urlopen`), printing
`PASS <name>` and exiting 1 on failure. The whole suite must stay green: `for t in tests/test_*.py`, with
`node tests/shots.js` and `python3 tests/test_web.py`.

## Who builds what

| Builder | Files | Features |
|---|---|---|
| A: Google | `server/google.py`, `server/gcal.py`, `web/features/calendar.js`, `tests/test_google.py`, `tests/test_gcal.py` | Google sign-in; Gmail (search, read, drafts, send through approval); Calendar tools; Drive (search, read, create Docs and Slides); the in-app calendar, mirroring Google Calendar plus any calendar links |
| B: Automation | `server/routines.py`, `server/workflows.py`, `server/subagents.py`, `server/media.py`, `web/features/routines.js`, `web/features/media.js`, tests | Routines and triggers; saved workflows; read-only research sub-agents; image generation |
| C: Acting | `server/browser.py`, `server/calls.py`, `web/features/calls.js`, `web/features/browser.js`, `Dockerfile`, tests | A headless browser Theta drives (submitting or buying needs approval; logins from 1Password or Bitwarden; the user can watch and take over on Theta's screen); phone calls to the user, and to others with disclosure and approval |
- A server feature may define `intercept(bot, text, user_msg)`: it can claim a chat message before the model
  (the intro takes typed answers this way) and returns the assistant messages it sent, or None.
- `/api/chat` takes an optional `show`: the label the chat stores in place of `text` (a tapped option's prompt
  still reaches the model; `meta.prompt` keeps it).
- Contacts (`server/contacts.py`, Settings > General): people Theta can text, call or email by name; tools
  `find_contact` and `save_contact`. Texting (`server/texts.py`): `send_text`, a send tool through Twilio SMS.
- Picking a request back up (`server/resume.py`): when a request fails because an app isn't connected, or a
  draft waits on one, it's saved; once the app connects, Theta texts first and carries on (a waiting draft
  gets Approve / Discard again; anything else runs again as a tool turn).
- Gmail and Calendar actions (`server/gactions.py`): archive, mark read and restore run directly (undoable);
  trash, unsubscribe (one-click link or mailto, never a blind web page), delete and move an event need Approve.
- Reviewed texts: a send tool may define `auto(args, ctx, info)`; it returns (ok, text) when it handled the call,
  or None for the approval card (setting `ctx["auto_note"]` says why). `send_text` uses it: saved contact, a turn
  the user typed, nothing untrusted read this turn, and a reviewer model on another provider says send.
  Incoming texts: POST /api/texts/inbound (the Twilio number's messaging webhook), signed by Twilio.
- Full Drive (`server/gdrive.py`): list, folders, move, rename, copy, restore, save a chat photo; trash and share
  need Approve. Needs the full `drive` scope; an older sign-in gets one text with a one-tap reconnect card.
- Contacts also come from Google Contacts (synced every 12 h, `contacts.readonly`, People API) and from a .vcf
  import (iPhone, iCloud). The user's own entries win over synced ones.
- Approvals (`server/approvals.py`, Settings > Security > Approvals): each send tool asks first or runs without a tap.
  Outward ones (email, text, calls, invites, sharing, websites) only run alone in a turn the user typed that read no
  outside text. Waiting actions are `approval` cards with their own buttons (`web/features/approvals.js`);
  `decide_approval` writes the outcome back onto the card. A send tool's `auto` hook still runs first.
- Gmail archive / trash / mark read take a `query` (every inbox match, up to 2,000, one call). `gmail_filter` and
  `gmail_filter_delete` need `gmail.settings.basic`.
- The agent shows at most two progress texts per turn, and runs up to 10 steps.
- Call recordings (`server/recordings.py`): on unless "record_calls" is off. Calls to others open with "This call is
  recorded."; an objection on the call stops it and the audio is discarded. Twilio's recording is downloaded to
  `<data>/recordings/<call id>.mp3`, deleted at Twilio, served at /api/calls/audio/<id> (byte ranges), and kept 90 days.
  Call history (`/api/calls/history`, the "..." menu) shows it with the transcript.
- Phone provider (`server/telco.py`): Telnyx when TELNYX_API_KEY is set (TeXML calls, /v2/messages texts, Ed25519
  webhook signatures, TeXML recordings), else Twilio. calls.py, texts.py and recordings.py go through it.
- Call voice: the "call_voice" setting: a preset (Polly neural voices, Telnyx Kokoro) or {"kind": "elevenlabs",
  "voice_id", "model", "key_ref"} or the same with "kind": "fishaudio" (models s2.1-pro, s2-pro, s1); key_ref is a
  Telnyx integration secret holding that company's key.
- Models check (`server/modelcheck.py`, Settings > General > Models): which keys are present, what each tier uses,
  and a one-word test per model. A model name the key can't use is replaced by the closest working one from the
  provider's own list ("model_fixes" setting, applied in router.fixed()). Key aliases (CLAUDE_API_KEY,
  GOOGLE_API_KEY, ...) are adopted at start (models.KEY_ALIASES).
- Bank accounts (`server/bank.py`): SimpleFIN Bridge, read-only. A setup token is claimed for an Access URL kept in
  the database (or SIMPLEFIN_ACCESS_URL); tools bank_accounts, bank_transactions; cached 30 min (~24 calls/day).
- Password managers (`server/vault.py` + browser.py's browse_sign_in): 1Password through a service account token
  (OP_SERVICE_ACCOUNT_TOKEN), Bitwarden through the `bw` CLI (`server/bitwarden.py`: BW_CLIENTID/BW_CLIENTSECRET
  log in, BW_PASSWORD unlocks, BW_FOLDER limits it; TOTP codes computed from the seed, RFC 6238). Logins are used
  only on a page whose host matches the item's saved website; values never reach the model.
- Account (`server/account.py`, `web/features/account.js`): profile (name, nickname, photo, email, phone,
  occupation, home, time zone, about, instructions; name/phone/tz share the call_name/phone/tz settings) and
  personalization (style, warmth, enthusiasm, emoji, memory on/off), turned into account.prompt_block() in the system
  prompt. storage() says whether the data dir is on the Railway volume (wipes are shown, not silent); backups via
  SQLite's backup API with SECRET_SETTINGS removed; restore keeps current secrets and a safety copy; daily Drive
  backups (last 7) with full Drive access; usage from the turns table; /api/logout.
- Intro and quiz (`server/onboarding.py`, `server/intro_steps.py`, `server/quiz.py`): hello, Theta's name, Make it yours
  (accent color, globe dots, opening: the "look" setting, GET/POST /api/look, web/features/look.js), style, feel
  (warmth, enthusiasm, emoji), phone and email, ground rules (Instructions), notifications, alerts near you (rounded
  location + texting first), apps to connect (each shows its setup), Google if picked, then an optional 14-question
  quiz, mostly checklists with "Other" for your own words (skip any; "stop" ends it).
  Answers go to the Profile (occupation, home, "More about you" lines keyed by topic) and Personalization; then a
  summary and chip ideas from the answers (built-ins to switch on, a tailored Morning brief, Meal plan, News digest,
  Catch me up on <interest>, Goal check-in, Keep in touch, Find a time) added with a tap. POST /api/onboarding
  {quiz: true} runs the quiz alone (Settings > Profile or General). While a question is open the model is told so.
- Chips (`server/chips.py`, `web/features/chips.js`): skills. Built-ins (Morning brief, Inbox sweep, Plan my day,
  Best price, Money check) plus the user's own; the ones on are listed in the turn context, chip_open loads one,
  chip_save makes one. A row of chips sits above the empty chat box. Settings > Chips edits them.
- Settings is a list of pages (root, profile, personalize, memory, chips, notifications, usage, data, security,
  connections, general); Theta.settings(title, page) adds a section to a page; Theta.emit("settings-page").
- Web search (`router.search_context`): Tavily, else a Bing search read in a private tab of Theta's browser
  (`browser.web_results`, its own session: not on Theta's screen, never saved as sign-ins). `router.search_live()`
  says whether either can run.
- Files (`server/files.py`): POST /api/files (raw bytes, X-File-Name), text pulled from PDF (pypdf), Word, Excel and
  text-like files; a chat message's "files" ids put their text in an outside-content frame and taint the turn;
  file_read; GET /api/files/<id>. Photos: the app uploads its JPEG after the message (attachImages).
- Self-improvement log (`server/improve.py`, after arXiv 2611.18856): each feedback lesson is recorded as an edit with
  a prediction and baseline; after 8 newer rated replies it gets a verdict (helping / not helping); one not sticking is
  stated more strictly; lessons made with another model are marked for a re-check. Shown on each lesson in Settings.
- Status line (`server/activity.py`): agent.run emits `activity` {id, text, state, kind} per tool call in plain
  words (contact names, page titles, element labels; never bodies, typed text, URL paths or secret-looking text);
  tools add steps through ctx["activity"](text, kind); the texts go on the reply as meta.activity, with
  meta.timing {total_ms, first_ms}. "Thinking it through" shows before the first step and isn't kept.
- Theta's screen (`server/live.py`, `web/features/live.js`): /api/live (state), /api/live/frame.jpg (CDP JPEG,
  scaled, ≤4 fps), /api/live/act (the user's own taps, typing, keys, scroll, back, reload, goto; a page's confirm()
  comes back to the user, and only their OK accepts it), /api/live/signins (list, DELETE signs out). A floating
  live picture shows while a turn browses; a reply that browsed carries meta.screen (the last picture).
- Browser (`server/browser.py`): reads iframes (refs f1e3) and shadow DOM, role widgets and pointer-styled
  elements; actions click, type, select, hover, key, scroll (to a ref), wait (seconds or words), upload (a photo the
  user sent), back. Popups and new tabs are adopted; dialogs are reported (an approved submit accepts its confirm);
  Enter in an autocomplete box is allowed with form submission blocked. Sign-ins persist in
  <data>/browser/signins.json. Real-Chromium checks: tests/test_browser_real.py against tests/site/.
- Search first: the persona and tool guide tell the model to search instead of guessing or saying it doesn't know.
- Home (`server/home.py`, `web/features/home.js`): GET /api/home {hello, date, stack, found, news}; DELETE
  /api/home?id= takes a find off. The smart stack is built from stored data only (approvals, reminders due, the next
  event found in tick, Theta's latest text, a storage warning). home_post (write, a core tool) saves a find (deal,
  news, watch, place, idea, update) to Found for you; deals fade after 7 days, news after 3. Top stories come from
  public RSS feeds (NPR, BBC, PBS, CBS) every 30 min, the ones matching Profile "Into:" lines first.
- Suggested chips (`server/chiphub.py`, `web/features/chiphub.js`): once a week (and on "Look for more") Theta reads
  the skill collections in its sources (GitHub repos with `.claude-plugin/marketplace.json`; default
  anthropics/skills), frames each SKILL.md as outside content, and has the quick model rewrite it into a chip that
  uses only Theta's tools, or skip it (needs code, developer-only). Suggestions show in Settings > Chips with their
  full steps and source; only Add makes one a chip. GET/POST /api/chips/suggested.
